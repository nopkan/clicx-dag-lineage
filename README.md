# CLICX Lineage

Airflow monitoring and Terry AI, built with Python, HTML, CSS, SVG and local Parquet. No JavaScript.

## Run locally

```sh
.venv/bin/python -B app.py
```

Open <http://127.0.0.1:8765>.

- **Import data** signs in to AWS (your browser opens if the SSO session expired), downloads every `dp_dag_lineage_export` date from `s3://uat-sss-dpf-dpt-thl-01-cnsmp/dag_lineage/` and opens the newest. The first page sets the S3 folder and environment (AWS profile: `LINEAGE_AWS_PROFILE`, default `nonprod_DP_DataEngineerOS`); it needs the AWS CLI (included in the Docker image).
- The top-bar picker switches between Data Platform and Risk Team (the two Airflows) and between saved dates. Refresh imports again. If AWS is unreachable, Import offers the data downloaded earlier.

See [DAG lineage export](docs/dag-lineage-export.md).

On a new machine:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B app.py
```

Python 3.10+ is required. The `-B` flag avoids generated bytecode folders. `python -m lineage_app` is an equivalent entry point. Options: `--port 8766`, `--data-dir /path/to/cache`, and `--host` (localhost by default).

## Folder layout

```text
app.py                   Local startup entry point
lineage_app/
  server.py              HTTP routes and collection jobs
  paths.py               Resource and data locations
  ai/                    OpenAI tools, queries and chat history
  clients/               Airflow API client
  data/                  Monitoring model, Parquet and raw data
  views/                 Python HTML/SVG rendering
  config/                Monitoring schema and declared DAG links
  templates/             HTML templates
  static/                Styles, icons and wordmark
tests/                   Self-contained regression tests
scripts/                 Container smoke check
docs/                    Architecture and Docker notes
data/                    Saved snapshots and chat database (local, ignored)
```

`.env` stays at the project root. Use `.env.example` for the supported OpenAI variable names. Credentials, data and `.venv` are excluded from Docker images.

## Test

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Tests use temporary snapshots, a fake Airflow server and a fake OpenAI client. HTTP tests require local socket binding. No private Excel workbook or live API key is required.

## Docker

The image `clicx-lineage:local` has been built and tested. The test container runs at <http://localhost:8766>, using its own data volume with a copy of the saved UAT snapshot. The normal Python app can keep running on port 8765.

```sh
LINEAGE_PORT=8766 docker compose -p clicx-lineage-test up -d --no-build
```

See [Docker setup and validation](docs/docker.md) for build commands, storage, testing and shutdown.

See [architecture and data behavior](docs/architecture.md) for the full design.
